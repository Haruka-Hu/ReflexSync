# 通信协议说明

核对日期：2026-10-19。固件协议以 [capture_common.h](../lib/capture_common/capture_common.h) 和 [capture_common.cpp](../lib/capture_common/capture_common.cpp) 为准，上位机解析在 [scope48_mvc.py](../tools/scope48_mvc.py)。

## 1. 三条独立链路

| 链路 | 用途 | 格式 |
| --- | --- | --- |
| Master ↔ Slave | 同步、状态命令、IMU、ACK | ESP-NOW 二进制 |
| Master ↔ 采集上位机 | 采集控制、EMG / IMU / 诊断、重传 | 上行二进制；下行按行文本 |
| Motor ↔ 电机上位机 | 参数、动作、状态、轨迹 | USB / BLE 共用换行文本协议 |

电机不承载 IMU 无线采集数据，也不接收 Master 的 START_STREAM。

## 2. 编号与状态

source：EMG=0x00、Gyro=0x01、Accel=0x02、Master 诊断=0x7E。

采集状态：IDLE=0、SYNC=1、STREAM_PENDING=2、STREAM=3。START_STREAM 先发送约 500 ms 后生效的 Master 时刻；STOP 返回 IDLE。

## 3. ESP-NOW 类型

| type | 消息 |
| --- | --- |
| 0x10 | Beacon |
| 0x11 | IMU ACK |
| 0x12 / 0x13 | 状态命令 / 状态 ACK |
| 0x14 / 0x15 | 双向同步探针 / 回复 |
| 0x16 | 无线配置 |
| 0x20 | IMU wire batch |
| 0x21 | 同步诊断 |

默认信道 1、速率 2 Mbps。Slave 每 20 点一批，约 50 批/s。20 ms 发送超帧中 slave-01 从 +2 ms 窗口发送，slave-02 使用 +10 ms 和 +15 ms 窗口；重传与回调时序仍会影响实际到包节奏。

### IMU wire batch：固定 176 字节

多字节整数按小端编码；轴值为有符号 int16。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | type=0x20 |
| 1 | 1 | source |
| 2 | 2 | batchSeq |
| 4 | 4 | sampleStartSeq |
| 8 | 1 | count，1–20 |
| 9 | 1 | flags |
| 10 | 4 | baseTimeUs |
| 14 | 160 | 20 个样本槽位，每槽 8 字节 |
| 174 | 2 | CRC16 |

每槽为 `dtUs:u16 + x:i16 + y:i16 + z:i16`，时间戳为 baseTimeUs + dtUs；有效样本序号为 sampleStartSeq + 槽位索引。count 小于 20 时空口长度仍不变。

flags：0x01=重传，0x02=已标记时间同步，0x04=链路故障。不能把 0x02 误当成故障，也不能把“已同步”理解为经外部仪器标定的绝对时间精度。

ACK 使用连续 batch 基准与 32 位接收位图。Master 去重后转发；Slave 释放已确认的缓冲槽，重发未确认批次。状态命令使用同序号重复发送，重复 ACK 不应重新启动采集。

### 校验与时间边界

IMU batch 和下述 PC 二进制帧使用 CCITT CRC16，初值 0xFFFF、多项式 0x1021，CRC 以小端放在末尾；不包含 CRC 自身。Beacon 是 packed 的 type / beaconSeq / state / masterTimeUs，不能把任意消息都当作相同的 CRC 封包。

microsecond 时间戳为 uint32，存在回绕；batchSeq 为 uint16。比较序号或时间应使用回绕兼容的差值，不能简单按数值大小判断前后。

## 4. Master → PC

所有 PC 帧以 `AA 55 type` 开始，但各 type 的头部布局不同。

| type | 内容 | 长度 |
| --- | --- | --- |
| 0x30 | 通用样本批次，当前也用于诊断 | 5 + count × 24 + 2，最多 16 点 |
| 0x31 | 同步诊断 | 24 |
| 0x32 | 状态事件 | 14 |
| 0x33 | 48CH EMG 批次 | 6 + 14 + count × 144 + 2，最多 4 点 |
| 0x34 | 原样封装 IMU wire batch | 4 + 176 + 2 = 182 |

0x30 的头部为 `AA 55 type count frameSeq:u8`，单样本包含 source、timestampUs、sampleSeq、batchSeq、flags、三个 int32。

0x33 的头部为 `AA 55 type count frameSeq:u16`；14 字节批次元数据为 timestampUs、sampleSeq、drdyCount（三个 u32）、flags:u8、保留字节。每个样本 48 个有符号 24-bit 小端通道值；同批后续点按 500 µs、序号 +1 重建。

0x34 的头部为 `AA 55 type frameSeq:u8`，随后是完整的 176 字节无线批次，最后还有外层 CRC。它没有额外的 count 字节，count 位于内层 IMU 批次。

0x31：头部 4 字节（含 u8 frameSeq），随后 source、state、beaconSeq、offsetUs、driftPpm、residualUs、beaconCount，最后 CRC。

0x32：头部 4 字节，随后 source、state、commandSeq、effectiveMasterTimeUs，最后 CRC。

序号、CRC、sample_seq、drdy_count 和队列指标分别描述不同层面的连续性，不能只用其中一个证明整条链路无丢失。

## 5. PC → Master

命令以换行结束：

| 命令 | 作用 |
| --- | --- |
| PING | 返回当前状态事件，通常不是纯文本 PONG |
| START_SYNC | 广播同步并进入 SYNC |
| START_STREAM | 计划统一开始采集 |
| STOP | 返回 IDLE |
| RADIO 1 2M | 配置信道和空口速率，变更后重新同步 |
| RESEND / NACK | 请求缓存中的 PC 帧，具体格式由 SerialReader 发送 |

Master 的主要返回是二进制状态／数据帧，不能用电机文本解析器替代采集解析器。

## 6. 电机 USB / BLE

标识 `HAMMER_COAST_V7`，protocol=2。广播 `Rotary_Hammer_BLE`；上位机兼容 `Neuro_Hammer_BLE` 缓存名。Nordic UART UUID：

- Service：`6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- RX 写入：`6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- TX 通知：`6E400003-B5A3-F393-E0A9-E50E24DCCA9E`

连接后查询 `INFO → STATUS → PARAMS → TUNING`，确认版本和参数再允许操作。命令包括 ZERO、HOME、JOG、SET、START、RETRACT、FIRE、STOP、TUNE、TRACE。`!` 走优先停止请求；正常文本命令按行封帧。

设备回复有 `OK`、`ERR`、`STATUS`、`PARAMS`、`TUNING`、`EVT` 和轨迹分块。BLE 通知可能把一行拆为多段，LineBuffer 负责重新拼行。新一击会覆盖固件缓存中的旧轨迹。

五档是上位机 JSON 配置；当前电机不再使用旧 STRIKE_n / SET_STRIKE 接口。详细操作与输出模式见 [电机控制说明](电机控制说明.md)。
