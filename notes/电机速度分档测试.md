# 电机速度分档测试

入口：`scripts/motor_speed_sweep.py`，Pixi任务：`motor-sweep`。默认回撤角度沿用本机当前使用的50°；档位表`hammer_profiles.json`不会被修改。

## 运行

在仓库根目录，关闭占用同一电机的上位机或其他测试客户端后执行：

```bash
# 查看计划；不会连接设备
pixi run motor-sweep --dry-run

# 正式测试：默认BLE，300/400/500/600/700/800/900°/s，各20次
pixi run motor-sweep

# USB方式；将端口换成实际电机端口
pixi run motor-sweep --mode USB --port /dev/cu.usbmodem1101
```

总计140次FIRE。BLE默认查找`Rotary_Hammer_BLE`，也识别旧缓存名`Neuro_Hammer_BLE`；可用`--device 名称或地址`指定。脚本不会自动重连。

可选参数：

```bash
# 单档单次，便于先核对流程
pixi run motor-sweep --speeds 300 --repeats 1

# 修改回撤角度、每击间隔或输出目录
pixi run motor-sweep --angle 50 --pause 2 --grade-pause 5 --output outputs/motor_sweeps
```

默认同档每次保存完数据后休息2秒，换档前休息5秒。归零、回撤和轨迹下载另需时间，140次完整测试可能运行十几分钟或更久。

## 每次动作的顺序

1. 查询STATUS，确认IDLE并持续静止至少200ms。
2. 发HOME，等待固件完成低速向前接近、停转和自动归零；检查接触候选与零点有效标志。
3. 再确认机构静止、零点有效。HOME已经在固件中执行编码器归零，无需再发JOG或在悬空位置发ZERO。
4. 设置本次回撤角度和目标速度，并用PARAMS回读核对。
5. 发RETRACT，等待READY并核对到位角度。
6. 发一次FIRE，等待本次shot的结束事件。
7. 完整下载并校验该击轨迹，保存结果后再进入下一次。

HOME使用当前V11固件的40°/s接近目标及其原有PWM限制；脚本不改固件PID、HOME速度或档位文件。HOME仍以编码器停转作为接触候选，没有独立接触开关；目标位置和机构应与日常测试保持一致。

## 结果位置和含义

默认输出始终在本工程的`outputs/motor_sweeps/`，与启动命令时所在目录无关。每次运行创建带微秒时间的新目录，避免覆盖旧数据：

```text
motor_sweep_日期_时间_微秒/
  run.json                      运行计划、完成数量、退出原因及STOP确认情况
  device.json                   固件INFO与速度环参数
  communication.log             带时间的完整收发日志
  summary.csv                   每次动作的结果，一行一击（异常尝试也保留）
  speed_300/
    trial_01/
      result.json               HOME、READY、结束事件、参数与编码器指标
      trace.csv                 时间、角度、速度、PWM等逐点轨迹
    ...
  ...
  speed_900/
```

`summary.csv`的主要列：

| 字段 | 含义 |
| --- | --- |
| speed_dps / trial | 目标速度与本档第几次 |
| fire_state | not_sent、sent_unconfirmed、acknowledged、completed，区分命令是否送达及动作是否有结束事件 |
| result / reason | 结束分类及固件结束原因 |
| home_travel_deg / ready_angle_deg | 本次HOME的移动量与回撤到位角度 |
| release_angle_deg / release_speed_dps | 检测结束时撤驱动的角度和速度；速度已经处于速降后，不是接触前速度 |
| early_drop_suspected | SPEED_DROP候选发生在−5°之前时标记True，供人工复核；阈值只是相对本次零位的诊断规则 |
| pre_drop_speed_dps / stable_ms / speed_qualified | 接触前估计区间的末点速度、稳速持续时间、是否满足±10%持续10ms的编码器速度指标 |
| trace_samples / error | 完整轨迹点数及异常说明 |

每档20次指20次FIRE动作，不表示独立确认了20次有效接触。当前固件曾观察到提前SPEED_DROP，脚本会记录`early_drop_suspected`；提前速降、越界或未检测到速降超时会急停并终止整轮，不自动补敲。实际接触和机械重复性需结合原始轨迹、靶面情况或独立测量判断。

## 中止与异常

- 按Ctrl+C中止，脚本优先发`!` STOP，再保存当前尝试的部分结果并关闭连接。Unix下SIGTERM走同样的取消路径。
- HOME/回撤故障、通信断开、动作确认超时、参数不一致或轨迹持续不完整时，终止整轮测试并尝试STOP；不重发动作、不自动重连、不自动续测。
- 只有轨迹读取会对缺失或CRC错误的分块重试，连续无进展最多重试3次。
- 每完成一击就保存文件并刷新汇总；中止时已保存的数据保留。写盘失败同样会触发停机处理，但故障磁盘上的数据完整性无法保证。
- `run.json status=completed`表示全部计划动作已记录且STOP得到确认；`stop_unconfirmed`表示动作结束但STOP未得到确认，程序返回失败状态。
- 正常结束和异常退出都尝试STOP；STOP或BLE断线后零点无效，再次手动操作前重新建立接触零位。

## 同步加速度与V11保护（2026-10-20）

```bash
# Master端口按实际USB设备身份确认；电机默认BLE
pixi run motor-sweep --master-port /dev/cu.usbmodem1CDBD499C8A01
# 先联调三次
pixi run motor-sweep --master-port /dev/cu.usbmodem1CDBD499C8A01 --speeds 300 --repeats 3
# 离线重算，不连接硬件
pixi run motor-sweep --analyze-run outputs/motor_sweeps/<本次目录>
```

Master先同步（Accel至少30个Beacon、残差绝对值不超过3000us），等待连续1秒有效样本；到位后取得200ms静止基线，再FIRE。窗口包含200ms前段、本击结束后1秒尾段及500ms迟到包收齐期；关闭窗口后才允许下一次HOME。下载电机轨迹时Master持续独立读取。

整段accel_raw.csv保留原始counts、时间戳、样本序号、flags及主机单调时间；每击accel.csv去重排序后配对，支持32位回绕。capture_events.jsonl保存同步、链路和动作标记，report.md及分档统计/图片支持离线重算。缺失不按零处理，不插值平滑后取峰值；未标定为g，不宣称峰值瞬间的精确角速度。多事件按全动作窗口阈值保守标记，启动振动也可能被标记，不可直接当作二次接触。

V11将两路速降证据允许的时差限制在3ms；主动下击超过相对接触零位+8°或反向越过回撤目标5°立即制动并清除归零，1800ms下击超时也制动。批量程序遇到超时、提前速降或异常结束立即终止；HOME实际行程达到8°在固件中立即制动；零点修正值只作诊断，不能视为真实绝对角度漂移。同步模式另检查锤头在接触点和回撤位的200ms三轴中位数，较本组参考差超过6 counts时停止（要求传感器刚性固定在锤头）。加速度连续1秒无新样本、USB断开或写盘失败时先急停Motor，再STOP Master；不自动重连。

本机已确认Master MAC为1C:DB:D4:99:C8:A0，Motor为C4:9E:7E:17:C3:2C。Master TinyUSB运行口和引导口名称不同，不可把电机的usbmodem1101误作Master引导口。端口身份写入本次master_identity.json。

### 分组实验

`pixi run motor-sweep --grouped --master-port <Master串口>` 将每档20次作为独立采集会话与目录；每组结束先STOP，再开始下一组。任一组失败停止后续组，不自动重连或补敲。`--speeds 300` 可仅做一组；未传 `--grouped` 保留原单会话方式。

分组模式组间会确认Master进入IDLE、Motor急停，并重建采集模型和文件；Master的底层USB句柄保持打开，避免macOS/TinyUSB反复开关口触发复位。若USB实际断开则整轮停止，不自动重连。
