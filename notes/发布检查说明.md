## 验证边界

这是静态检查、编译和离线软件验证。本次没有烧录、驱动电机或重新进行整套系统的实机采集；不能据此声称机械安全、叩击重复性、USB/BLE 链路或跨节点同步精度已经在所有硬件上验收。电机接触候选及加速度原始计数的限制见 README 和电机控制说明。

## 保留的边界问题

录制仍沿用秒级文件名，短时间重复录制可能重名；使用者明确要求不修改这一行为。当前录制写盘线程也没有完整的磁盘故障恢复：若写入因磁盘满或设备错误而异常退出，停止时可能等待队列而阻塞。此项已识别并记录，本次保持录制实现原样；实验前应确认保存位置可写且空间充足。

## 2026-10-20 电机 V8 修正验证

- `master`、`slave-01`、`slave-02`、`motor` 四个构建目标通过。
- `pixi run python -m unittest discover -s tests -v`：16 项通过。覆盖 BLE 任意分片、分片丢失／粘连／数值损坏、CRC、过时请求、V7 兼容、缺点重读上限、不干扰动作确认、不完整／坏时间戳轨迹禁止导出。
- C++ 测试编译真实编码器、运动控制器及命令封帧源码，使用 GPIO/PCNT/时钟模型验证方向、500 次故意漏 GPIO 中断的往返、计数限值接续、归零、READY、下击超时、STOP、控制周期异常和计数器失败；并用 Python 接收器检查固件输出的 CRC 格式。
- 当前用户五档参数与修改前逐字节一致；tools 仍为 8 个运行文件。测试源码单独放在 tests，不连接设备。
- 本轮没有烧录、驱动电机或测量机械重复性。V8 的 BLE 实际传输和连续叩击位置偏移，需要烧录电机后复测；离线计数模型不能排除真实波形噪声、机械回差或连接松动。


## 2026-10-20 电机 V9 回撤修正与实测

V9已写入电机板并通过Flash哈希校验。修正静止于20°积分区外时不补力的问题，静止Ki从40改为80；原750ms无进展、8s回撤超时和PWM/积分上限仍保留。增加BLE断线原因、停机上下文及工程内运行日志。

离线回归18项通过。实际MainWindow/TransportWorker通过BLE连续运行300.006秒，明确执行接触候选位置ZERO后，15次50°回撤均到READY，没有意外ABORT/断线/命令错误。主机测得回撤耗时0.919–1.022秒；READY角度-50.00–-49.17°。本轮BLE重试、队列丢弃、截断累计值均为0。每轮结束后由测试脚本主动STOP，不计作异常制动。

旧V8本轮未复现用户此前的中途BRAKE；缺少原日志，不能断定那次的直接触发原因。测试还发现单次下击在−44.38°提前产生SPEED_DROP候选；虽然30点轨迹CRC读回通过，该次未作为有效叩击验收。接触判据和机械叩击重复性仍需进一步验证。原始日志与结果在本地outputs中，不随源码发布。
