# 采集上位机使用说明

对应 [scope48_mvc.py](../tools/scope48_mvc.py)，核对日期：2026-10-19。

## 1. 连接与采集

```bash
pixi run scope48-mvc --ads-gain 6
```

当前固件 PGA 增益为 6，上位机默认值仍为 4，因此启动时应显式填写。当前窗口标题包含 v3，以区分旧脚本；默认存储位置由脚本所在仓库决定。

1. 选择 Master 的串口并手动连接。端口列表自动刷新，不会自动重连。
2. “开始同步”发送 START_SYNC，观察两种 Slave 的在线和同步指标。
3. “开始采集”发送 START_STREAM，进入等待开始阶段后统一启动 EMG / IMU。
4. 需要保存时点击“开始录制 CSV”。只开始采集不会自动创建录制文件。
5. 结束时停止录制，或点击 STOP 一并结束录制和采集。

无线信道／速率设置变更后应重新同步。不同节点必须使用兼容的信道和速率。电机的动作由独立电机界面控制，不由此处的采集 START / STOP 统一驱动。

## 2. 显示和 MVC

EMG 原始／滤波显示与保存数据是不同路径。显示滤波包括 50 Hz 陷波和 20–450 Hz 带通；实时显示可抽取，原始录制不因此降采样。

MVC 使用所选 16 通道组，按每通道滑动 RMS 后取中位数。默认 RMS 窗口 250 ms、反馈更新 50 ms；不是三轴合力或关节转矩。

界面引导标定：静息 5 s，三轮试次，每轮前倒计时 3 s、试次 5 s，轮间休息 30 s。每轮取最高的 0.5 s 滑动均值，三轮最高值作为 MVC 参考。数据缺口可使试次无效，需要按界面重做。

反馈计算：

```text
EMG %MVC = 100 × max(当前 RMS − 静息 RMS, 0) / (MVC RMS − 静息 RMS)
```

有效标定要求 MVC 高于静息值。改变采集条件、增益或通道组时应重新核对标定，不能把以前的参考值无条件用于新的实验条件。

## 3. 保存什么

默认在当前仓库 `data/` 中创建：

| 文件 | 内容 |
| --- | --- |
| `emg48_capture_时间.bin` | 原始 EMG 二进制帧，录制期间直接写入 |
| `emg48_capture_时间.csv` | 停止后由 BIN 转换的 48 通道原始计数 |
| `imu_capture_时间.csv` | source、时间戳、序号、flags、三轴计数和 vector_norm |
| `sync_diag_时间.csv` | 同步 offset、drift、residual 等诊断 |
| `mvc_feedback_时间.csv` | MVC 幅值反馈、目标、阶段等 |
| `mvc_calibration_时间.json` | 计算配置与标定信息 |

因此，录制过程中暂时没有 EMG CSV 不代表没有保存。停止后的转换、分析和绘图在后台进行，结果显示在界面分析区。

默认波形图放在当前仓库 `outputs/waveforms/`。相对 `--csv-dir` 以仓库根目录解析，绝对路径按用户指定保存录制数据；波形输出仍在当前仓库。控制区显示两个完整目录。

## 4. 必要依赖文件

- [analyze_data.py](../tools/analyze_data.py)：录制后的 IMU 连续性／速率分析。
- [view_emg48.py](../tools/view_emg48.py)：EMG 波形图片生成。
- [view_waveform.py](../tools/view_waveform.py)：IMU 波形图片生成。

这三个文件由界面通过子进程调用，不能因为没有手动启动就删除。

## 5. 如何判断数据是否完整

综合检查 sample_seq 缺口、重复、时间间隔、rx_flags、CRC、hostdrop、Master qdrop 和录制队列丢弃。每秒收到的点数有波动，不一定等于最终丢样；软件时间戳约 1000 Hz 也不等于传感器物理采样相位完全已知。

STOP 会结束当前录制并清空当前采集／显示状态；完成的 MVC 参考值可按现有逻辑保留。断开后需手动重新连接。

原有秒级录制文件名按使用者要求保留。异常写盘与快速重复录制的边界见 [发布检查说明](发布检查说明.md)。实验文件和生成图片已被 Git 忽略，不随源码上传。
