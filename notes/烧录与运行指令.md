# 烧录与运行指令

核对日期：2026-10-19。以下命令均在仓库根目录运行。

## 1. 环境

```bash
pixi install --locked
pixi run platformio device list
```

Pixi 管理 Python、图形库、串口、BLE 和 PlatformIO；构建平台固定为 `espressif32@6.13.0`。不要把 `.pixi/` 当作可跨机器复制的安装包。

## 2. 构建

```bash
pixi run build-master
pixi run build-slave-01
pixi run build-slave-02
pixi run build-motor
```

也可一次编译四个目标：

```bash
pixi run platformio run -e master -e slave-01 -e slave-02 -e motor
```

这只是编译，不执行烧录或硬件动作。

## 3. 烧录

先断开占用串口的上位机。多块板同时连接时，应根据实际设备明确填写端口：

```bash
pixi run upload-slave-01 --upload-port <PORT>
pixi run upload-slave-02 --upload-port <PORT>
pixi run upload-motor --upload-port <PORT>
```

`<PORT>` 替换为实际端口，例如 `/dev/cu.usbmodem...` 或 `COM3`，不要原样输入尖括号。默认 Slave 是 4 MB Flash，电机是 N16R8，见 [硬件接线与参数](硬件接线与参数.md)。

Master 使用 TinyUSB，运行时端口与 ROM 引导端口可能不同：

```bash
pixi run upload-master --port <RUNTIME_PORT> --rom-port <ROM_PORT>
```

该脚本通过 1200 baud 请求进入引导，再调用 `platformio run -e master -t upload`。脚本还保留原开发机的默认端口，换电脑时应显式指定两个参数；可用 `--help` 查看。设备已经处于 ROM 模式时，脚本直接使用指定 ROM 端口。

## 4. 运行上位机

```bash
# 当前 Master 固件增益为 6；此参数影响幅值换算
pixi run scope48-mvc --ads-gain 6

# 电机界面
pixi run motor-host
```

两个上位机均手动连接，不要求启动时就接好设备。采集界面中“开始同步”“开始采集”“开始录制 CSV”是不同操作。电机界面需要先完成协议与参数确认，再进行归零和动作。

常用参数：

```bash
pixi run scope48-mvc --ads-gain 6 --port <MASTER_PORT>
pixi run scope48-mvc --ads-gain 6 --csv-dir data/subject/session
pixi run motor-host --mode USB --port <MOTOR_PORT>
pixi run motor-host --mode BLE --device Rotary_Hammer_BLE
```

这些参数预选连接目标，实际连接仍由界面操作触发。

## 5. 串口诊断

```bash
pixi run platformio device monitor --port <SLAVE_OR_MOTOR_PORT> --baud 115200
```

监视器不能与上位机同时占用同一串口。Master 输出二进制帧，普通文本监视器不适合查看其采集数据。

Slave 每秒有 `NODE_DIAG`，可查看温度、采样率、设备 ID、漏采、发送与队列状态。停止状态可使用 `STATUS`、`DIAG_CPU 80/160/240`、`DIAG_IDLE_PS ON/OFF`、`DIAG_STREAM_PS ON/OFF`；这些覆盖只在本次上电有效。`tx_timeouts` 只是等待回调超时次数，不等同于丢样。

## 6. 当前任务边界

当前 Pixi 任务只包含两个上位机与固件构建／烧录。历史 `host`、`scope48`、`motor-monitor`、`motor-ports`、`test-*`、独立诊断任务均已移出。串口列表使用 PlatformIO 命令，录制后分析由采集界面自动调用其运行依赖。
