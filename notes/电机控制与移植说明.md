# ReflexSync 电机控制说明

2026-10-19 从 `rotary_hammer_contact_coast` 移植。固件在 `src/motor/`；采集 Master 和两个 Slave 使用各自的独立构建目标。

ESP32-S3 电机控制固件，配套 PySide6 + pyqtgraph 上位机，支持 USB 串口和 BLE。当前固件标识为 `HAMMER_COAST_V7`，协议版本为 `2`。

本页说明新电机模块。采集系统入口仍为 `scope48-mvc` 等 Pixi 任务。

## 1. 启动上位机

本机终端运行：

```bash
cd ReflexSync
pixi run motor-host
```

首次在新电脑或新目录安装环境时，先运行：

```bash
pixi install
```

本机已有 `.pixi/` 环境，可直接启动。复制工程到其他电脑后，应根据 `pixi.toml` 和 `pixi.lock` 重新安装环境。

也可直接使用 Python 入口：

```bash
pixi run python tools/motor_controller.py
```

当前工程没有双击启动脚本，使用以上命令启动。

## 2. 连接设备

USB 和 BLE 在界面中二选一，均为手动连接、断开和重连。

| 方式 | 操作 |
|---|---|
| USB | 选择设备串口，点击“连接”；串口波特率为115200 |
| BLE | 选择BLE，输入设备名或地址，点击“连接” |

BLE 输入默认名为 `Neuro_Hammer_BLE`，同时兼容固件广播名 `Rotary_Hammer_BLE`。系统缓存旧名称时通常不需要修改名称。

连接后，上位机依次读取 `INFO → STATUS → PARAMS → TUNING`。显示“已连接 · 协议与参数已确认”后才可以操作；仅建立串口或蓝牙连接不代表参数已确认。

上位机、串口命令行工具和烧录程序不要同时占用同一个串口。

## 3. 日常操作

### 一键叩击

1. 将锤头静止放在约定的物理零位。
2. 连接设备，点击“当前位置归零”。编码器显示0°本身不代表物理位置正确。
3. 设置回撤角度和目标速度，或编辑五档表格。
4. 点击“一键回撤 → 叩击”或五档按钮。上位机会先下发并回读参数，再发送启动命令。
5. 固件完成回撤、到位稳定、速度闭环叩击；检测到速度突降后撤驱动，返回IDLE。
6. 在“速度与轨迹”页查看曲线、结束原因和速度指标，按需导出CSV与配套JSON。

正常完成后保留编码器零点，静止后可再次启动。STOP、手动移动、异常退出或单片机重启后，需要重新确认物理零位并归零。

当前 `hammer_profiles.json` 保存的五档为 **200、250、300、350、400°/s**，回撤角度均为 **60°**。修改后点击“保存五档配置到本地”，下次启动继续使用。若配置文件缺失或无效，程序回退到内置的200、400、600、800、1000°/s五档。

**1000°/s档此前出现接触漏检，尚未通过实机验收。** 首次使用从200°/s开始；输入框允许填写的范围不代表机构允许的机械行程。

### 分步操作

- **仅回撤**：回撤到目标角度并保持，进入READY，等待手动FIRE；不会自动叩击。
- **叩击 FIRE**：在READY且满足到位条件时启动下击。
- **STOP**：中止当前动作、制动并清除零点有效标志。
- **按住正转／反转**：以±40°/s为目标低速调整，松开停止。手动移动后需重新归零。
- **慢速接近靶面并归零（HOME）**：向固定靶面慢速接近，持续停转后把该位置设为零；完成后保持IDLE，不自动叩击。

HOME仅根据编码器停转推断接触，机械卡滞也可能产生假零点。40°/s是控制目标，不是机械速度的硬上限。

### 参数和轨迹

- 五档表格保存到本地 `hammer_profiles.json`。
- 回撤角度、目标速度在动作前下发并回读确认。
- 调参页提供 `KP、KI、KS、KV、KG`，只在IDLE时修改。
- 单片机上的动作参数和调参值保存在RAM，重启恢复源码默认值；当前没有自动写入Flash。
- 叩击轨迹在固件中缓存，结束后分块读取；读取可以取消，只有完整轨迹允许导出。
- 新一轮FIRE会覆盖上一轮固件轨迹，需要保留的数据应及时导出。

## 4. 构建、烧录和串口调试

在工程目录运行：

```bash
# 构建固件
pixi run build-motor

# 列出串口
pixi run platformio device list

# 上传到指定设备（将端口替换为实际值）
pixi run upload-motor --upload-port /dev/cu.usbmodem1101

# 串口监视器
pixi run platformio device monitor --port /dev/cu.usbmodem1101 --baud 115200
```

Windows端口通常为 `COM3` 等，使用 `pixi run platformio device list` 查看实际端口。

烧录前断开上位机。电机常用任务为 `motor-host`、`build-motor`、`upload-motor`；其他采集任务继续保留。

## 6. 控制逻辑与硬件

四个状态保持为：

```text
IDLE → RETRACT → READY → STRIKE → IDLE
```

START把回撤和叩击串联；单独RETRACT在READY等待。HOME和JOG复用RETRACT模式，不增加状态。

- **控制周期**：1ms，使用实际时间间隔计算；实时闭环运行在单片机，上位机负责设置、显示和保存数据。
- **回撤控制**：回撤与READY使用同一套连续位置控制，避免到位边界处输出跳变。低速时积分补偿静差，接近停转时加快积分建立；不改变原有PWM上限与退出保护。
- **到位条件**：角度误差绝对值≤1.2°、速度绝对值≤20°/s，连续130ms。
- **叩击控制**：`PWM = KS + KV × 目标速度 + KG × sin(角度) + KP × 速度误差 + 积分`，允许短暂反向PWM抑制超调。
- **接触候选**：根据编码器速度突降判断，独立于是否已达到目标速度；不能代替力传感器。
- **退出**：回撤超时8秒；距目标超过3°且750ms没有足够位置进展时退出；下击最长1.8秒。

硬件与默认参数集中在 `src/motor/control_config.h`：

| 项目 | 配置 |
|---|---|
| 主控 | ESP32-S3，当前构建配置为16MB Flash、8MB Octal PSRAM |
| 电机驱动 | DRV8871，IN1=GPIO41、IN2=GPIO42 |
| 编码器 | A=GPIO39、B=GPIO40，16PPR×4倍频×27减速比 |
| 角度分辨率 | 约0.2083°/count |
| PWM | 20kHz、10bit，软件限幅±1000 |
| 默认速度参数 | KP=3、KI=20、KS=−96.7、KV=0.4477、KG=3.25 |

## 7. 通信与状态判断

USB与BLE共用按行文本协议。命令以换行结束，`!`可优先请求停止。BLE使用Nordic UART风格UUID：

| 通道 | UUID |
|---|---|
| Service | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX写入 | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX通知 | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |

| 命令 | 用途 |
|---|---|
| `INFO` / `PING` | 固件协议信息／通信查询 |
| `STATUS` | 状态、角度、速度、实际输出及结束原因 |
| `ZERO` | 静止且IDLE时，将当前位置定义为零位 |
| `HOME` | 慢速接近固定靶面并建立零位 |
| `JOG 40` / `JOG -40` | 低速手动移动；需持续刷新，350ms无刷新自动撤驱动 |
| `SET 60 200` / `PARAMS` | 设置／读取回撤角度和目标速度 |
| `START` | 一键回撤并叩击 |
| `RETRACT` / `FIRE` | 分步回撤／叩击 |
| `STOP` / `!` | 停止并制动，零点失效 |
| `TUNING` | 读取速度环与前馈参数 |
| `TUNE 3 20 -96.7 0.4477 3.25` | 按KP、KI、KS、KV、KG顺序设置参数 |
| `TRACE 0` | 从指定索引读取最近一击轨迹，每次至多8点，仅IDLE可读 |

`STATUS`中的 `state` 表示流程状态；`output` 表示实际驱动模式，两者不要混淆：

| 输出模式 | IN1 / IN2 | 含义 |
|---|---|---|
| `FORWARD` | PWM / 0 | 正向驱动 |
| `REVERSE` | 0 / PWM | 反向驱动，回撤时通常出现 |
| `COAST` | 0 / 0 | 撤去驱动，允许惯性滑行 |
| `BRAKE` | 1023 / 1023 | 主动制动，STOP或异常退出后可出现 |

正常接触和下击超时使用COAST。`pwm=0`不能单独证明两路均为0，应结合 `output、in1、in2` 判断。BRAKE本身不是故障状态，停止后仍显示BRAKE是正常行为。

回撤检查字段：`reason`为最近动作原因，`pos_error`为到位误差，`settled_ms`为稳定计时，`phase_ms`为阶段耗时，`auto_fire`表示是否等待自动叩击。

## 8. 常见问题

| 现象 | 检查方式 |
|---|---|
| 连接后五档按钮不可用 | 查看状态栏是否待归零、正在动作或正在确认参数；先完成物理归零 |
| BLE找不到设备 | 检查主控供电与电脑蓝牙；使用广播名、旧缓存名或设备地址，关闭其他占用该设备的客户端 |
| 固件协议未确认 | 查看通信日志，确认设备使用本工程固件；可在调参页重新读取设备参数 |
| 回撤附近停住、不下击 | 看主操作页原因及 `state`；READY且使用“仅回撤”时应手动FIRE；若超时或无进展，先检查机构和零位 |
| 回撤后看到REVERSE或BRAKE | 这是输出模式；结合流程状态和结束原因判断，不以输出模式单独判断卡住 |
| 烧录或串口打开失败 | 关闭其他串口监视器，并断开上位机后重试 |
| 轨迹读取较慢 | BLE分包传输需要时间，可取消；新动作会取消未完成的读取 |

轨迹CSV记录时间、角度、反馈速度、原始速度和PWM，配套JSON记录参数及指标。速度指标按接触前估计区间内误差±10%、连续至少10ms计算；速度指标满足不等于已确认接触，未检测到接触的超时不算叩击成功。

## 9. 验证边界

当前固件和上位机使用协议 2，旧 `STRIKE_n`、`SET_STRIKE`、`MOTOR_FWD/REV` 不再作为本版本接口。五档由上位机 `hammer_profiles.json` 管理。

发布前已做四个固件编译和上位机离线验证，详见 [发布检查说明](发布检查说明.md)。实机动作、USB/BLE 通信和机械重复性仍需要结合实际硬件验收。历史实测数据、Flash 备份和本地移植记录不随源码上传。
