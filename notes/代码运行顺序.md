# 代码运行顺序

核对日期：2026-10-19。本页沿当前真实入口说明“谁创建对象、谁调用、何时启动硬件”。

## 1. Master 上电

```text
src/master/main.cpp
  全局 g_app(Config)：保存引脚和串口配置
  Arduino setup()
    → MasterApp::begin()
      → USB、队列、ADS1298 与 ESP-NOW 初始化
      → 创建 wireless / serialCommand / serialTx / sensor 任务
  Arduino loop()
    → 永久阻塞
```

构造函数不等同于开始采集。采集状态由串口命令切换；ADS DRDY 中断通知采样任务，SPI 读取在 sensorTask 中完成。

```text
采集界面点击“开始同步”
  → SerialReader.send_text_command("START_SYNC")
  → Master 串口命令任务 → handlePcCommand → transitionTo
  → 广播状态命令与 Beacon → Slave 回复状态／同步诊断

点击“开始采集”
  → START_STREAM → STREAM_PENDING
  → Master 与 Slave 等待 effectiveMasterTimeUs
  → 进入 STREAM → 开始传输采样数据
```

## 2. Slave 上电与采样

```text
src/slave-01/main.cpp 或 src/slave-02/main.cpp
  g_app(Config)：source、发送偏移、传感器、引脚、CPU
  setup() → ImuSlaveApp::begin()
    → 设置 CPU / 串口 / 测温
    → 初始化选中的 MPU6500 或 ADXL375 驱动
    → ESP-NOW、收包队列、发送完成信号量
    → 创建 wirelessTask 与 sensorTask
```

当前两板不接传感器 INT。sensorTask 在自己的核心上创建硬件定时器；未进入 STREAM 时关闭定时采样，开始后每 1 ms 通知任务读取一次三轴。

```text
定时器 ISR → 任务通知 → sensorTask
  → 检查当前状态和漏采
  → localToSampleTimeUs
  → readSensor → readGyro / readSample
  → 20 点 → storeBatch → 本地环形缓冲

wirelessTask
  → 处理下行队列、命令、同步和 ACK
  → updateRadioPower
  → 发送窗口内取候选批次 → sendPacket
  → 完成回调更新状态并唤醒发送等待
```

同步拟合先取快照再做计算；Wi-Fi 收包回调不承担长时间 SPI 或拟合操作。

## 3. 采集界面与录制

```text
pixi run scope48-mvc --ads-gain 6
  → parse_args：路径相对工程解析
  → 创建 AcquisitionModel、QApplication、MainWindow
  → 显示窗口、自动刷新端口列表
  → 用户点击连接后才创建并启动 SerialReader
```

SerialReader 分开处理串口接收与解析，按 type 和 CRC 更新模型。界面定时刷新图形、指标和 MVC；MVC 只使用需要的通道数据和自己的反馈窗口。

```text
开始录制 → AcquisitionModel.start_recording
  → EMG 原始帧写 BIN，IMU／同步写 CSV
  → MainWindow._start_mvc_recording 保存 MVC 反馈
停止录制 / STOP → _finish_recording
  → 等待当前写入结束、关闭文件
  → 后台 _analyze_recording_files
    → BIN 转 EMG CSV
    → IMU 分析
    → 生成 EMG／IMU 波形图片
```

当前秒级文件命名及异常写盘边界保持原实现，见 [发布检查说明](发布检查说明.md)。

## 4. 电机固件与界面

```text
src/motor/main.cpp
  全局 motor、encoder、motion
  setup()
    → 创建命令／USB 输出／BLE 输出队列
    → motion.begin：驱动与编码器初始化
    → initBle
    → 创建 1 ms 控制任务与定时器
  loop()
    → 解析 USB 字符、刷新输出、处理重新广播
```

USB 与 BLE 字符进入 LineParser，再入命令队列；控制任务处理请求并调用 MotionController.update。STOP / ! 使用优先请求，在控制任务中清命令队列并执行停止。BLE 断线也请求停止。

正常 START 流程为 `IDLE → RETRACT → READY → STRIKE → IDLE`。单独 RETRACT 到 READY 后等待 FIRE；HOME / JOG 复用回撤状态中的模式。结束原因和输出模式应分别查看。

```text
pixi run motor-host
  → motor_controller.py → hammer_gui.main
  → MainWindow + TransportWorker
  → 用户连接 USB 或 BLE
  → INFO / STATUS / PARAMS / TUNING 确认
  → 参数下发、回读后执行动作
  → 动作结束后分块下载轨迹 → 指标／导出
```

实时控制留在 MCU 内，上位机负责设置、显示和保存，不通过 Python 定时循环闭环驱动电机。
